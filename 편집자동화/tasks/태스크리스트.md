작성: 2026-10-04

## 공통 원칙

### 1. 모든 태스크는 같은 5단계 구조로 만든다
**입력 → 분석(Detect) → 판단(Decide) → 실행(Execute) → 검수(Verify)**

- Detect와 Decide는 **후보 목록(JSON)만 만들고 타임라인을 건드리지 않는다.**
- Execute는 승인된 후보만 Premiere에 적용한다.
- Verify가 실패하면 Execute를 되돌리고(이전 버전 시퀀스로 복귀) 실패 사유를 남긴다.

### 2. 태스크끼리는 파일로 데이터를 주고받는다
에이전트가 서로의 대화 맥락에 의존하지 않도록, 모든 결과를 `work/<프로젝트명>/` 아래 파일로 남긴다.

| 파일 | 만드는 태스크 | 쓰는 태스크 |
|---|---|---|
| `brief.json` | 0 | 전체 (판단 기준) |
| `manifest.json` | 1 | 2, 3, 4, 23 |
| `sync_map.json` | 2 | 3, 4, 5, 9 |
| `transcript.json` (문장·단어 타임코드, 화자) | 5 | 6, 7, 10, 12, 13, 15, 17 |
| `edit_decisions.json` (컷 목록 + 삭제 사유 + 보존 사유) | 6, 7 | 8, 9, 22 |
| `cues.json` (포인트자막·자료화면·그래픽·SFX·BGM 위치) | 10, 13, 15, 17, 19, 20 | 14, 16, 18, 19, 20 |
| `qc_report.md` | 8, 22, 24 | 사람 검수 |

### 3. 단계마다 버전 시퀀스를 남긴다
`v01_sync` → `v02_audio` → `v03_rough1` → `v04_rough2` → `v05_multicam` → … 처럼 단계마다 시퀀스를 복제해서 작업한다. 결과가 나쁘면 해당 단계만 다시 돌린다.

### 4. 사람 검수 게이트 (🔒)
아래 지점에서는 자동으로 다음 단계로 넘어가지 않고 사용자 승인을 받는다. 승인된 결과만 `docs/learnings.md`에 기록한다.
- 🔒 G1 싱크 완료 후
- 🔒 G2 1차 가편집 후
- 🔒 G3 2차 가편집 후 (내용 삭제는 되돌리기 어렵다)
- 🔒 G4 인트로 하이라이트 확정 전
- 🔒 G5 렌더링 전

## 태스크 목록

### 0. 기획 브리프 입력 *(추가)*
판단(Decide) 단계에 기준이 있어야 해서 맨 앞에 추가했다.
- 영상 목적 / 주제 / 핵심 메시지
- 타깃 플랫폼 (YouTube 가로형, 쇼츠 등)
- 목표 러닝타임
- 출연자 목록, 화자 이름, 캐릭터 (보존할 말버릇 포함)
- 채널 스타일 가이드 (자막 폰트·색, 포인트 자막 템플릿, SFX·BGM 라이브러리)
- 고유명사·전문용어 사전 (STT·맞춤법 교정용)
- **출력:** `brief.json`

### 1. 프로젝트 초기화
- 프로젝트 폴더 구조 생성

- A캠 / B캠 / 외부 오디오 식별
- 해상도·FPS·오디오 샘플레이트 확인
- **FPS·샘플레이트 불일치 경고** *(추가)* (예: 29.97 vs 30, 44.1k vs 48k)
- **오프라인·손상 미디어 확인** *(추가)*
- 파일명 규칙 정리
- 필요 시 프록시 생성
- 작업용 시퀀스 생성 (시퀀스 설정 = A캠 기준)
- **출력:** `manifest.json`

### 2. 멀티캠 싱크

- 싱크 오차 확인 (허용치: 1프레임 이내)
- 장시간 촬영 시 오디오 드리프트 확인
- **카메라 녹화 끊김(파일 분할) 구간 처리** *(추가)*
- 기준 오디오 트랙 지정 (외부 오디오 우선)
- 불필요한 카메라 오디오 비활성화
- 멀티캠 소스 시퀀스 생성
- 메인 편집 시퀀스 생성
- **출력:** `sync_map.json`, 시퀀스 `v01_sync` · 🔒 G1

### 3. 오디오 전처리
- 스테레오 음성을 모노로 변환
- 좌·우 채널 이상 여부 확인 (한쪽만 녹음된 경우)
- 노이즈 제거
- 저역 노이즈 제거 (하이패스 약 80Hz)
- 화자 간 음량 차이 보정
- EQ 적용
- 컴프레서 적용
- 리미터 적용
- 레벨 기준 설정 (memo 기준값 반영)
  - 화자 음성: **-6 dB**
  - SFX: **-10 dB**
  - BGM: **-18 ~ -21 dB**
- **최종 라우드니스 목표 정의** *(추가)*: YouTube 기준 통합 -14 LUFS, True Peak -1 dBTP
- 클리핑 여부 확인
- **출력:** 시퀀스 `v02_audio`

> 메모: 위 dB 값이 피크 기준인지 클립 게인 기준인지 확정 필요 → `docs/decisions.md`

### 6. 1차 가편집 — 규칙 기반 컷
- 영상 시작 전 준비 구간 제거
- 영상 종료 후 불필요 구간 제거
- 긴 무음 탐지 (기준값 정의 필요, 예: 0.7초 이상)
- 불필요한 긴 무음 축소 또는 삭제 (남길 호흡 길이 정의, 예: 0.2~0.3초)
- NG컷 탐지
- 재촬영 구간 탐지 → **여러 테이크 중 가장 좋은 테이크 선택** *(추가)*
- 촬영 관련 스태프 대화 제거
- "어", "음", "그…" 등 의미 없는 필러 탐지
- 의미 없는 필러 삭제
- "이제, 이제부터" 등 말 더듬기 제거
- 문장 재시작 구간 제거
- 동일 단어 반복 제거

**예외 규칙**
- 감정이나 망설임 자체가 의미를 가지는 경우 보존
- 화자의 캐릭터나 말맛을 만드는 표현은 보존 (`brief.json` 참조)
- 삭제 시 문장의 의미가 달라지는 경우 보존
- **웃음·리액션은 보존** *(추가)*

- **출력:** `edit_decisions.json` (모든 컷에 삭제 사유, 모든 보존에 보존 사유), 시퀀스 `v03_rough1` · 🔒 G2

### 9. 멀티캠 컷전환 *(순서 변경: 기존 11 → 9)*
인트로를 본편 클립으로 만들기 때문에, 본편 컷전환을 먼저 끝내면 인트로에서 컷전환을 다시 할 필요가 없다.
- A캠을 기본 화면으로 설정
- A캠 비중 70~80% 유지
- B캠 비중 20~30% 기준 적용
- Jump Cut 발생 구간 B캠 전환 (8에서 표시한 지점)
- 손동작 강조 구간 B캠 전환
- 몸동작 강조 구간 B캠 전환
- 감정 변화 구간 B캠 전환 후보 생성
- **리액션 샷 전환** *(추가)* (듣는 사람의 반응, 화자↔카메라 매핑 사용)
- 문단 전환 시 화면 변화 검토
- 긴 A캠 지속 시 B캠 전환 검토 (기준 정의 필요, 예: 15초 이상)
- 부자연스러운 편집 지점 B캠으로 은폐
- 기계적인 일정 간격 컷전환 방지
- **B캠 최소 지속 시간** *(추가)* (예: 1.5초 미만 전환 금지)
- **출력:** 시퀀스 `v05_multicam`, A/B 비중 리포트

## MVP 1단계

**0 → 1 → 2 → 3 → 4 → 5 → 6 → 8**

| 태스크 | 실행 수단 | 난이도 메모 |
|---|---|---|
| 0 브리프 | 사용자 입력 + 템플릿 | 쉬움 |
| 1 초기화 | Premiere MCP (import, 시퀀스 생성) | 쉬움 |
| 2 싱크 | 외부 스크립트(오디오 상호상관) 또는 Premiere 동기화 기능 | MCP에 직접 싱크 도구가 없어 검증 필요 |
| 3 오디오 | Premiere MCP 오디오 이펙트·레벨 | 노이즈 제거 품질은 외부 도구가 나을 수 있음 |
| 4 화면 정규화 | Premiere MCP (scale/position/rotation) | 수평·샷사이즈 판단은 프레임 캡처 + 비전 분석 필요 |
| 5 Transcript | Premiere 내장 Speech to Text (사용자가 전사·내보내기) | 단어 타임코드·신뢰도 확인됨. 전문용어 오인식은 문맥 검토로 보완 |
| 6 1차 가편집 | transcript.json + Premiere MCP 컷 | **효과가 가장 큰 구간** |
| 8 컷 QC | 규칙 검사 + 프레임 캡처 | 중간 |

**권장:** 2·4는 판단이 어려우므로, 처음에는 **5 → 6(무음·필러 제거)**을 먼저 끝까지 만들어 파이프라인 구조(JSON 계약, 버전 시퀀스, 검수 게이트)를 검증한 뒤 나머지를 붙이는 것을 추천한다.
