# 실패 기록 (참고 금지)

사용자가 불만족한 결과. 학습 근거로 쓰지 않는다. 같은 실수를 피할 때만 "하지 말 것" 용도로 본다.

## [공통] 기준 판정을 즉석 측정으로 해서 틀린 결론 → 불필요한 작업 (2026-10-21, 오디오 재확인)
- 무엇: 오디오 결과를 에이전트 검증 도구가 아닌 즉석 코드·다른 지표로 재서 "기준 밖"으로 잘못 보고 → 사용자가 새 시퀀스·게인 변경을 결정하게 만듦 (자세히 agents/오디오/failures.md)
- 사용자: "잘못한 부분은 복기 확실하게 해서, 추후 동일한 일이 벌어지지 않도록 꼭 유의해"
- 모든 에이전트에서 하지 말 것:
  - 기준(criteria)으로 판정할 때는 **그 에이전트의 검증 도구·정의된 지표로만**. 도구가 없으면 기존 검증 기록(report·log)에 적힌 방법과 같은지 먼저 확인
  - **이전 결과와 정반대가 나오면** 그럴듯한 설명(편집이 바뀌어서 등)으로 넘기지 말고 같은 방법으로 이전 결과를 다시 재서 비교한 뒤 보고
  - 사용자에게 조치를 제안하기 전에 근거 수치를 **어떤 방법으로 쟀는지** 밝히고, 예상과 다른 결과(3 dB 올렸는데 0.4 dB만 오름 등)는 바로 멈추고 원인부터 확인

## [공통] 요청을 넓게 해석해 큰 작업으로 바로 감 (2026-10-21, 포인트 자막 길이)
- 무엇: "포인트 자막 길이가 더 연장이 안 되는데"를 "템플릿 자체 길이를 늘려 달라"로 해석해 AE 템플릿 30초 연장(범위·길이 질문까지 함)으로 진행하다 사용자 정정 — 실제 뜻은 "트랙에 올린 클립을 끌어서 6~7초로 늘리고 싶다"(원인: 클립 원본 끝점 out이 템플릿 끝에 남음)
- 하지 말 것: 증상 설명형 요청은 **먼저 현재 상태를 재현·측정해서 원인부터** 보고하고, 해결 범위가 큰 작업(템플릿 파일 수정 등)은 해석을 한 줄로 확인한 뒤 진행


## [공통] 이전 영상 스크립트를 복사해 쓰다 빈 번호가 그대로 남아 다른 영상 빈에 시퀀스를 넣음 (2026-10-27, 근감소증 학회)
- 무엇: `근감소증 학회_컷편집_rough`를 만들 때 터틀볼 작업의 복제 스크립트를 그대로 가져다 씀. 그 안의 `app.project.rootItem.children[4]`(터틀볼 빈 번호)가 남아 있어 새 시퀀스가 `터틀볼 의자 운동/시퀀스`로 들어감. 결과에 빈 이름을 같이 찍어서 바로 알아채고 근감소증 빈으로 옮김 (그 뒤 단계는 번호를 고쳐 진행)
- 사용자: "실수는 반복되지 않도록 원인 파악해서 잘 기록해두고."
- 원인:
  1. 빈을 이름이 아니라 **순서 번호**로 찾음 — 최상위 빈은 가나다순(극락 0 · 근감소증 1 · 매트 2 · 체어 3 · 터틀볼 4 · 자료 5 …)이라 영상마다, 빈이 늘 때마다 번호가 바뀜
  2. 이전 영상 스크립트를 재사용하면서 **영상에 따라 바뀌는 값**(시퀀스 ID·빈·작업 폴더)을 바꾸다 빈 번호를 놓침 — ID·경로는 눈에 띄지만 번호는 안 보임
  3. 넣은 뒤 **어느 빈에 들어갔는지 확인하는 단계가 없었음**
- 하지 말 것 / 대신 할 것:
  - 시퀀스 복제는 `scripts/common/clone_seq.jsx`로만 — 원본 시퀀스가 있는 빈을 찾아 같은 빈에 넣고, 넣은 뒤 빈을 다시 확인해 "(확인)"을 돌려줌 (2026-10-27 근감소증·터틀볼 두 영상으로 시험, 시험 시퀀스는 지움)
  - `rootItem.children[번호]` 같은 번호로 빈·항목을 고르지 않는다. 꼭 필요하면 이름으로 찾고 결과에 이름을 찍는다
  - 이전 영상 스크립트를 재사용할 때는 실행 전에 영상별 값(시퀀스 ID·빈·작업 폴더·시간 값)을 모두 찾아 바꿨는지 훑어본다
  - 공통 규칙은 `agents/README.md` "작업 시작 전" 3번에도 적어 둠

## 2026-10-27 이미지 클립 길이 늘릴 때 끝부분 사라짐 (노년 필수근육 매트안내 레이어 분리)
- 증상: PNG를 overwriteClip 후 `clip.end`만 늘렸더니 소스 outPoint는 기본 길이(5초)에 그대로 → 불투명도 끝 키가 5초 지점에 찍혀 5초 뒤부터 안 보임.
- 원인: 정지 이미지는 `end`를 바꿔도 outPoint가 따라 늘지 않음. 키는 inPoint~outPoint 기준으로 계산함.
- 방지: 정지 이미지 길이 바꿀 때는 `outPoint = inPoint + 길이` 먼저 → `end` 설정 → 그 다음 키 추가. 확인은 클립 **뒷부분** 시각에서도 프레임을 뽑아 볼 것.

## 2026-10-27 같은 이름 클립이 두 개일 때 엉뚱한 쪽을 교체 (노년 필수근육 발 리사이즈)
- 증상: 89.49초 클립을 바꾸려고 이름으로만 찾았는데, 사용자가 같은 세트를 453.09초에 복사해 둬서 마지막에 찾은 453.09초 쪽이 교체됨 (결과는 같은 설정이라 피해 없음, 89.49초도 이어서 교체).
- 원인: 직전 조회 후 사용자가 타임라인을 직접 고침 + 이름만으로 클립 선택.
- 방지: 클립은 이름 + 시작 시각(트랙)으로 함께 고른다. 사용자가 손댄 뒤에는 바꾸기 직전에 다시 읽는다.
- 참고: 사용자가 프리미어에서 그림을 키우면(크기 165%) 깨짐 → 키운 비율만큼 큰 PNG를 새로 만들어 크기 100으로 교체 (위치·회전·불투명도 키 유지).

## 2026-10-27 오디오 클립 교체 시 새 곡이 원래 길이로 들어가 다음 곡 앞부분을 덮음 (노년 필수근육 BGM 교체)
- 증상: A3 Funky Chunk(106.77~210.68)를 지우고 Do It Boy(3:14)를 overwriteClip → 곡 전체 길이로 들어가 301.3초까지 차지, 299.73초에 시작하던 Enter the Party 앞 1.6초가 잘림. 그 뒤 이름+시작 시각으로 찾던 2번 곡을 "못 찾음"으로 알게 됨. 2번 곡도 교체 대상이라 원래 구간(299.733~368.201)으로 새 곡을 넣어 피해 없음.
- 원인: overwriteClip은 소스 전체 길이로 놓고, 길이는 그 뒤에 줄임 → 줄이기 전에 같은 트랙 뒤 클립을 덮어씀. 여러 곡을 앞에서부터 차례로 교체하면서 각 클립의 원래 구간을 미리 다 저장해 두지 않음.
- 방지: 같은 트랙에서 여러 클립을 바꿀 때는 ① 모든 클립의 시작·끝·in·볼륨·전환을 먼저 기록 ② **뒤쪽 클립부터** 교체하거나, 새 소스가 원래 구간보다 길면 다음 클립과의 간격을 확인 (가능하면 add_to_timeline의 sourceIn/Out로 필요한 길이만 넣기) ③ 끝나고 트랙 전체를 다시 읽어 원래 구간과 비교.
- 참고: 클립을 remove 하면 붙어 있던 오디오 전환(지속 가감속)도 사라짐 → QE `item.addTransition(tt, true=시작/false=끝, '00;00;초;프레임', '00;00;00;00', 0, true, false)`로 다시 넣음.

## 2026-10-27 유튜브 레퍼런스의 두 번째 오디오 트랙(자동 더빙 영어)을 원본으로 착각 (놀심 레퍼런스 분석)
- 증상: mp4 오디오 트랙 2개 중 비트레이트 높은 두 번째(AAC-LC 127k)를 "고음질 원본", 첫 번째(HE-AAC 48k)를 "저음질 재압축"으로 판단 → 받아쓰기가 영어로 나옴. r4 한 편 + r1~r3 분리 일부를 다시 돌림.
- 원인: 두 트랙 상관이 0에 가까운데도(내용이 다르다는 신호) 음량 비교만 보고 "같은 소리"로 결론. 언어를 확인하지 않음.
- 방지: 레퍼런스에 오디오 트랙이 2개 이상이면 각 트랙 앞 20초를 받아쓰기 언어 감지(faster-whisper `info.language`)로 먼저 확인하고 원본 언어 트랙을 고른다. 유튜브 다운로드본은 자동 더빙 트랙이 붙어 있을 수 있음.
