# 결정 사항

## 2026-10-04 최종 검수는 사용자가 직접 한다
- QC 에이전트는 만들지 않는다.
- 이유: 최종 판단은 사용자가 직접 하기로 함.

## 2026-10-04 에이전트는 확실히 필요한 것부터 하나씩 만든다
- 첫 번째: 컷편집 에이전트 (agents/컷편집/)
- 에이전트마다 criteria / learnings / failures / log 를 따로 가지고 학습한다 (agents/README.md).

## 2026-10-04 자막·Transcript는 외부 플러그인을 사용한다
- 자막 담당 에이전트는 당분간 만들지 않는다.
- (2026-10-05) 자막은 컷편집이 끝난 뒤 진행한다. 컷편집 에이전트는 자막을 넣지 않는다.
- (2026-10-05, 위 결정 보완) **자막 에이전트를 별도로 만든다.** 컷편집 전에 음성 인식·검토로 transcript를 만들어 컷편집에 넘기고, 컷편집 후 최종 자막을 완성한다. 외부 플러그인 대신 쓸지는 음성 인식 엔진 결정 시 확정.
  - 이유: transcript가 없으면 컷편집이 필러·NG·말더듬을 판단할 수 없다.
- 최종 자막은 Premiere 자막 트랙에 바로 넣는다 (SRT → import → create_caption_track).

## 2026-10-05 자막 에이전트 최종 방식: Whisper 파이프라인 (사용자 확정)
- **자막 에이전트는 agents/자막/AGENT.md를 따른다** (사용자가 작성한 자막 요구사항을 통합한 문서).
- 음성 인식: **로컬 Whisper(faster-whisper large-v3)**, 문맥 단위(최대 25초)로 인식하고 결과는 단어 단위로 보관.
- 단어 시간: wav2vec2 한국어 모델로 강제 정렬. **Claude는 텍스트만 교정하고 시간은 만들지 않는다.** 교정 후 다시 정렬.
- 애매한 구간: 앞뒤 2.5초 재인식으로 후보를 만들고 후보 중에서만 고른다. 뜻이 반대로 갈리면 원문 유지 + 질문.
- 확인: 애매한 곳은 대화로 질문(한 번에 최대 10개), 답으로 학습 (corrections.md, glossary.md). 정답 자막 = 프로젝트 완성 후 사용자가 내보낸 최종 SRT.
- **Premiere 내장 전사(transcript.json)는 쓰지 않는다. Whisper로만 한다** (사용자 지시). 애매한 구간 후보도 Whisper 재인식(B~F)만 사용.
- 이 결정 이전의 자막 방식은 모두 대체됨: Premiere 전사 단독(2026-10-05 오전), 전체 사용자 검토 목록, 자주색 라벨 + SRT 비교.
  - 경위: Premiere 전사 단독 → Whisper 비교(정확도 부족으로 한때 제외) → 사용자 지시로 재시도 → 요구사항 기반 파이프라인 구현·검증(놓친 말 20%→4%, 단어 시간 오차 0.22→0.11초) → 사용자 확정
- 이유: 실제 발화 보존과 단어 시간 정확도가 가장 높았다.
- (2026-10-05 오후) v01_sync 테스트에서 Whisper 인식 정확도가 크게 부족 → **음성 인식 엔진을 네이버 CLOVA Speech로 바꾸는 중** (사용자 지시). 비교 테스트 후 확정. 나머지 파이프라인(정렬·교정·자막·Premiere)은 유지.

## 2026-10-04 컷편집 에이전트 운영 방식
- 실행 전 사전 확인: 초기에는 매번 하고, 몇 번 연속 승인되면 생략한다 (기준: 컷편집/criteria.md).
- 태스크: C1~C6, C8~C11 적용. C7(재촬영)은 삭제하지 않고 모든 테이크를 남긴다.
- 이유: 테이크 선택은 사용자가 직접 한다.
- 삭제 방식: 잘라 내지 않고 클립 비활성화로 남긴다 (사용자가 되살릴 수 있도록).
- (2026-10-05) 테이크를 고를 때마다 선택 이유를 받아 agents/컷편집/take_choices.md에 기록하고, 반복되는 이유는 추천 기준으로 승격을 제안한다.

## 2026-10-04 프리미어 프로젝트 빈 구조
- 모든 프로젝트는 `촬영본` / `시퀀스` / `자료` 3개 빈으로 나눈다.

## 2026-10-04 싱크 에이전트를 가장 먼저 실행한다
- 같은 장면을 찍은 여러 카메라 클립을 오디오 기준으로 시퀀스에 겹쳐 배치한다 (agents/싱크/).
- 이유: 이후 편집에서 같은 순간의 카메라를 바꿔 가며 쓰려면 싱크가 먼저 맞아야 한다.
- 촬영 전체를 시퀀스 1개에 시간순으로 배치, 멀티카메라 소스 시퀀스 없이 트랙만 쌓는다, 오디오 트랙은 모두 켠다.
- 카메라 파일명 규칙은 쓰지 않는다 (프로젝트마다 다름) → 메타데이터로 구분하고 사용자에게 확인.
- 외부 녹음 오디오는 현재 없음 (카메라 내장 오디오만).
- 드리프트는 보정하지 않고 표시만 한다.
- A캠 판단: 각 클립의 프레임을 캡처해서 정면 구도와 넓은 샷이면 A캠 (길이 등 다른 근거는 쓰지 않음). 초기에는 캡처 화면과 근거를 보여 주고 확인받은 뒤, 규칙이 명확해지면(연속 3회 일치) 자동 확정으로 전환을 제안한다.
- 싱크 후 카메라 라벨: A캠 = 창포색(1), B캠 = 보라(0). 모든 프로젝트 기본.
- 장면 사이 간격 10초. 짝이 없는 클립은 시퀀스 맨 끝에 모으고, 마지막 싱크 장면과 1분 간격을 둔다. 짝이 없는 클립끼리는 10초 간격.

## 2026-10-05 자막 에이전트 역할 변경: 텍스트는 Cutback, 에이전트는 싱크·폭·위치
- **자막 텍스트는 Cutback 플러그인으로 만든다.** 사용자가 SRT로 내보내 `work/<프로젝트명>/subtitle/cutback.srt`로 넘긴다.
- 자막 에이전트는 **텍스트를 만들거나 고치지 않는다.** 하는 일: 영상 너비에 맞게 줄바꿈·나누기, 위치 지정, 실제 말소리와 싱크, 컷편집 반영, Premiere 자막 트랙 삽입 (agents/자막/AGENT.md).
- **CLOVA Speech 연결 해제** (키 파일·스크립트 삭제). Whisper 음성 인식도 쓰지 않는다. 오디오 강제 정렬(wav2vec2)은 싱크용으로 계속 쓴다.
- 이유: Whisper·CLOVA 모두 이 촬영 환경(카메라 내장 마이크, 겹치는 대화)에서 자막으로 쓸 만한 정확도가 나오지 않았다.
- 위의 "자막 에이전트 최종 방식: Whisper 파이프라인" 결정은 이 결정으로 대체된다.
- 자막 형식: **최대 1줄, Pretendard 55px.** **한 자막에 두 사람의 말을 넣지 않는다** — 다른 화자의 말은 짧아도 새 자막 (사용자 지시).
- (2026-10-05 보완) 자막 에이전트는 Cutback 자막의 **명백한 음성 인식 오류는 문맥으로 고친다** (용어·소리가 비슷한 말·맞춤법). 사용자가 고쳐 준 표현은 `agents/자막/glossary.md`에 쌓아 다음부터 자동 교정. 애매한 것은 묻는다. 텍스트를 새로 만들지는 않는다.

## 2026-10-05 오디오 에이전트 신설 (음량 맞추기)
- 목표 음량: **말소리 -4 ~ -6 dB, 배경음악 -18 ~ -21 dB, 효과음 -10 ~ -12 dB** (사용자 지정). agents/오디오/
- 원본은 건드리지 않고 복제한 시퀀스에서 클립 볼륨·키프레임으로 조절. 측정은 실제 오디오로.
- 측정 기준(피크/평균/LUFS)은 사용자 확인 전까지 Premiere 미터 피크(dBFS)로 해석.
