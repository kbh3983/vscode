# 포인트 에이전트

> 작업명: 포인트자막

## 역할
프리미어 프로 시퀀스의 대사를 분석해서, 대사의 감정·의도에 맞는 그래픽 템플릿(.mogrt)을 **포인트 자막**으로 배치한다.
최종 선택은 사용자가 하고, 에이전트는 **후보를 빠짐없이 깔아주는 것**과 **사용자의 선택을 기록해 다음 작업에 반영하는 것**을 책임진다.

- 하는 것: 포인트 구간 고르기, 구간마다 후보 템플릿 전부 배치(후보마다 다른 트랙), 텍스트 넣기, 후보 마커, 검토 결과 학습
- 하지 않는 것: 기본 자막(자막 에이전트), 컷 편집, 컷전환, 색보정, 오디오, 템플릿 파일 자체 수정

> 2026-10-10 신설 (사용자 지시: "포인트" 에이전트를 만들어줘). 다른 에이전트 파일과 섞지 않는다.

### 정해진 작업 (트리거)
| 사용자가 이렇게 말하면 | 따를 절차 |
|---|---|
| "포인트", "포인트 자막", "포인트자막" | 이 문서 5장 작업 순서 (승인된 결과가 생기면 `playbook_포인트.md`로 옮긴다) |
| "포인트 검토 완료" | 7장 학습 |
| "애프터이펙트 버전으로", "AE로 바꿔" (프리미어 템플릿) | [playbook_AE변환.md](playbook_AE변환.md) |
| "정렬", "가이드라인" | **정렬 에이전트로 분리됨 (2026-10-14)** → [../정렬/AGENT.md](../정렬/AGENT.md) |

## 1. 절대 규칙 (어떤 경우에도 예외 없음)
1. **원본 시퀀스는 절대 수정하지 않는다.** 클립 추가·삭제·이동·속성 변경, 트랙 추가, 마커 추가 모두 금지.
2. 작업은 항상 원본 시퀀스를 **복제**한 새 시퀀스에서만 한다.
   - 새 시퀀스 이름: `원본시퀀스명_포인트`
   - 같은 이름이 이미 있으면 덮어쓰지 않고 `원본시퀀스명_포인트_2`, `_포인트_3` … 순으로 만든다.
3. 그래픽 템플릿은 **"내 템플릿" 폴더에서만** 가져온다.
   - 경로: `%APPDATA%\Adobe\Common\Motion Graphics Templates`
   - Essential Graphics 패널의 Adobe Stock, 로컬 다른 폴더, 인터넷의 템플릿은 사용하지 않는다.
4. 복제한 시퀀스 안에서도 **기존 클립(영상·오디오·기존 자막)은 건드리지 않는다.** 포인트 자막은 새 비디오 트랙에만 추가한다.
5. 작업 중 오류가 나면 지금까지 만든 `_포인트` 시퀀스는 그대로 두고, 어디서 멈췄는지 보고한 뒤 중단한다. 원본을 되돌리려는 시도도 하지 않는다(원본은 애초에 건드리지 않았으므로).

## 3. 템플릿 해석 규칙
템플릿을 고를 때 참고하는 정보는 아래 순서로 중요도가 높다.

1. **학습 기록** — 비슷한 대사에서 사용자가 실제로 고른 템플릿
2. **템플릿 파일명** — 예: `화남_부정_강조.mogrt` → 감정 `화남`, 성격 `부정`, 용도 `강조`
3. **템플릿 안의 키워드·설명 정보** (메타데이터, 기본 텍스트 등)

파일명은 `_`로 나뉜 각 단어를 태그로 보고, 대사와 비교할 때 태그 단위로 판단한다.

### 매칭 예시
| 대사 | 판단 근거 | 후보 |
|---|---|---|
| "동작이 힘들어요" | 고통·불만 → 부정적 감정 강조 | `화남_부정_강조` |
| "와 진짜 대박이다" | 놀람·긍정 | `놀람_긍정_강조` 등 |
| "근데 이건 꼭 기억하세요" | 정보 강조 | `정보_강조` 등 |

(※ 위 템플릿 이름은 예시이며, 실제 후보는 폴더에 있는 템플릿 중에서만 고른다.)

## 4. 입력 / 출력
**입력**: Premiere 시퀀스 (사용자가 이름 지정), 대사 소스(2장), "내 템플릿" 폴더, `포인트_학습기록.md`
**출력** (`work/포인트/`): 템플릿 스캔 목록, 대사 목록, 배치 계획(처음 배치 상태 — 7장 비교 기준), `report.md`
Premiere: `_포인트` 새 시퀀스(새 비디오 트랙에 후보 템플릿 + 마커), 저장

## 5. 작업 순서
| 단계 | 하는 일 |
|---|---|
| **P1 시퀀스 복제** | 원본을 복제해 `_포인트` 이름 규칙대로 새 시퀀스를 만든다 |
| **P2 대사 수집** | 2장에서 정한 소스에서 대사와 시작/끝 타임코드를 가져온다 |
| **P3 포인트 구간 선정** | 모든 대사에 넣지 않는다. 아래 중 하나에 해당하는 대사만 고른다 |
| **P4 후보 템플릿 선정** | 대사 하나당 후보를 **최대 3개** 고른다 (2026-10-11 사용자 지정). 하나로 줄이지 않는다. **같은 스타일의 색상 변형은 하나만** (예: `강조말-노랑`과 `강조말-하늘`을 같이 넣지 않음) |
| **P5 배치** | 새 트랙에 후보별로 쌓고 텍스트·마커를 넣는다 |
| **P6 완료 보고** | 아래 형식으로 보고한다 |

### P3 포인트 구간 기준
- 감정이 뚜렷한 대사 (놀람, 화남, 웃음, 감동, 당황 등)
- 핵심 정보·결론·반전이 담긴 대사
- **운동 영상은 정보형이 중심** (2026-10-12 회고 반영): 동작 요령·주의점 → `요령`, 세트·횟수·시청자 참여 안내 → `세트안내`, 출연자가 대답 못 하거나 힘든 상태 → `해설`
- 문구는 대사를 그대로 옮기지 않는다: 요령 `윗줄 / 아랫줄` 요약·명령형, 세트안내 `앞 {강조} 뒤`, 해설 `[...]`, 감정·반응은 핵심 구절만 짧게 (criteria.md 문구 형식)
- 구간마다 `at`(그 말이 나오는 대사 구절)을 적는다 → 시작 시점. 반응 유형이면 그 장면 프레임을 보고 `who`(말한 인물: 왼쪽/오른쪽/가운데)를 적는다
- 효과·후기·변화를 말하는 대사는 **긍정** (놀람 아님, 2026-10-13)
- 설명형 영상의 정보·요약은 `정보` → `요약_색강조_한줄_AE` (명사형 요약, `{하늘}` `[초록]`), 제품 안내는 `제품안내` → `정보바_2줄_AE` (`윗줄 / 아랫줄`, `{노랑}`) (2026-10-13)
- points에 `genre`(운동/설명) — 강조 1순위가 다름. 해부·척추 설명 대사는 `image_prompt`(GPT용 설명 이미지 프롬프트, criteria 틀), 제품 결론 대사는 `suggest`에 반짝 강조 + 제품 사진 (2026-10-13)
- 엔딩 앞 60초 안의 웃음·마무리는 고르지 않는다 — points에 `ending`(엔딩 시작 초)을 적으면 plan.py가 뺌 (2026-10-13)
- 화면 효과가 어울리는 대사·제품 메시지는 `suggest`에 효과음·확대·화면 효과를 적는다 (제안만, 마커와 보고에 나옴)
- 학습 기록상 사용자가 포인트 자막을 남긴 유형과 비슷한 대사
- (2026-10-13 틀어진골반 회고) 정보 구간엔 `alts`(같은 템플릿에 넣을 다른 문구 1~2개)를 적는다. 문구 끝은 명사형, 결론은 행동형. 요령에 동작이 둘이면 구간을 둘로. 해설은 PD·출연자 속마음. 설명·시범 위주 교정 영상은 `genre: "교정"`(감정·반응 후보 안 냄). 설명 이미지 프롬프트는 1:1 작은 삽입용

### P5 배치 규칙
- 기존 최상단 비디오 트랙 위에 새 트랙을 추가해 배치한다.
- 후보가 여러 개면 **같은 타이밍에 후보마다 다른 트랙**으로 쌓는다 (후보1 → V(n+1), 후보2 → V(n+2) …).
- 학습 기록상 **1순위 후보**가 있으면 후보1(V(n+1))에 둔다.
- 클립 시작은 **그 말이 실제로 나오는 순간**, 길이는 유형별 (criteria.md 시작 시점·길이, `cue_words.py` → `plan.py`). (2026-10-12 이전: 대사 시작~끝)
- 템플릿의 텍스트 필드에 대사(또는 대사의 핵심 구절)를 넣는다. 템플릿 글자 수 한계를 넘으면 핵심 구절만 남긴다.
- 배치 후 모든 포인트 템플릿의 폰트를 **페이퍼로지 7Bold**로 바꾼다 (`criteria.md`, `scripts/point/set_font.jsx`).
- 문구를 바꿀 때 **글자 묶음 길이(`fontTextRunLength`)도 새 문구 길이로** 맞춘다 — 안 맞추면 폰트가 템플릿 원래 문구 길이만큼(앞 몇 글자)만 적용되고 나머지는 원래 폰트로 나옴 (2026-10-11 자세교정 V2 0:19 사용자 지적). apply_point·replace_ae·fix_twoline에 반영됨. 배치 후 `scripts/point/fix_runs.jsx`(FIX=false)로 어긋난 칸이 0인지 확인
- **정렬 (2026-10-13)**: 가이드선이 A 1028 / B 925 / C 840 / X 36 / Y 960으로 바뀜 — 한 줄 가운데·두 줄 왼쪽·Tip 세 줄은 정렬 에이전트([../정렬/AGENT.md](../정렬/AGENT.md))가 맞춘다. 배치 완료 보고 끝에 "정렬도 진행할까요?"를 붙인다. 아래 876~997 띠는 이전 기준
- **글자 크기 (2026-10-12 승인)**: 배치·폰트 처리 뒤 사용자가 준 가이드 띠(현재 y 876~997)에 한 줄 자막 글자 높이를 113px로 맞춘다 — `dump_points.jsx` → `fit_guide.py jobs` → `render_solo.jsx` → `fit_guide.py plan` → (확인 필요·두 줄 목록을 사용자에게 먼저 물음) → `apply_guide.jsx` → 다시 렌더 → `fit_guide.py verify`. 가이드가 바뀌면 사용자 스크린샷의 선을 재서 띠를 새로 정한다. 헷갈리는 것은 작업 전후로 묻는다
- **반응 자막 위치 (2026-10-12)**: 웃음·놀람·부정·화남은 말한 인물 머리 위(자리가 없으면 턱 밑) — `fit_person.py split`으로 나눈 뒤 반응은 `fit_person.py`, 나머지는 `fit_guide.py`. 정보형 4종은 그대로. 얼굴 못 찾음·인물 여럿인데 who 없음은 "확인 필요"로 묻는다
- 각 클립 위치에 마커를 달고, 마커 설명에 `후보: 화남_부정_강조 / 놀람_부정 …`처럼 후보 목록을 적는다. 효과 제안이 있으면 `제안: …`
- 배치가 끝나면 처음 배치 상태(구간·대사·후보·트랙·텍스트)를 `work/포인트/<시퀀스>_배치.json`에 저장한다 (7장 비교용).

## 6. 사용자 검토
- 사용자는 각 구간에서 원하는 후보 하나만 남기고 나머지는 지운다.
- 사용자가 텍스트를 수정하거나, 위치를 옮기거나, 전부 지우는 것도 모두 의미 있는 피드백으로 본다.
- 에이전트는 사용자가 **"포인트 검토 완료"**라고 할 때까지 `_포인트` 시퀀스를 건드리지 않는다.

## 7. 학습 (검토 완료 후)
사용자가 "포인트 검토 완료"라고 하면 `_포인트` 시퀀스의 최종 상태를 처음 배치한 상태(`work/포인트/<시퀀스>_배치.json`)와 비교해 [포인트_학습기록.md](포인트_학습기록.md)에 기록한다.

### 기록할 것
| 항목 | 예시 |
|---|---|
| 날짜 / 시퀀스 | 2026-10-10 / 운동브이로그_포인트 |
| 대사 | "동작이 힘들어요" |
| 깔아준 후보 | 화남_부정_강조, 당황_부정 |
| 사용자 결과 | **선택: 당황_부정** / 전부 삭제 / 텍스트 수정("힘들어요"만 남김) |

### 기록에서 뽑아낼 규칙
- 같은 유형의 대사에서 같은 템플릿이 3회 이상 선택되면 → 그 템플릿을 **1순위 후보**로 올린다. (다른 후보도 계속 함께 배치한다.)
- 특정 유형의 대사에서 매번 전부 삭제되면 → 그 유형은 **포인트 구간에서 제외**한다.
- 매번 텍스트가 짧게 수정되면 → 텍스트 길이 기준을 조정한다.
- 정리된 규칙은 학습 기록 파일 맨 위 `## 현재 규칙` 섹션에 요약해두고, 다음 작업 시작 시 이 섹션부터 적용한다.

### 공통 파일과의 관계
- 후보별 선택 결과는 `포인트_학습기록.md`에 쌓는다 (이 에이전트 전용, 사용자 지정).
- 작업 방식 자체에 대한 사용자 승인·불만족은 공통 규칙(`agents/README.md`)대로 `learnings.md` / `failures.md`에, 기준값은 `criteria.md`에 남긴다.
- 날짜별 작업 기록은 `log/YYYY-MM-DD.md`.

## 9. 기술 메모 (2026-10-11 확인)
- 배치: `dump_audio.jsx`(말소리 트랙) → `.venv/Scripts/python scripts/point/cue_words.py <audio.json> <srt> <points.json> <words.json>` → `scripts/point/plan.py <points.json> <srt> <배치.json> <words.json>` → `apply_point.jsx` (PLAN, AT=빈 오디오 트랙, 클립 이름 = 템플릿 이름) → `fix_twoline.jsx` → `set_font.jsx` → `fix_runs.jsx`
- 위치: `dump_points.jsx` → `fit_person.py split` → 띠(`fit_guide.py jobs/plan`)·인물(`fit_person.py jobs/plan`) → `render_solo.jsx`(jobs 경로는 **절대 경로**로 바꿔 넣기 — 상대 경로면 "folder doesn't exist") → `apply_guide.jsx` → 다시 렌더(a 접두) → verify. `fit_person.py`는 OpenCV가 필요해 **`.venv` 파이썬**으로
- 넣기 전에 비디오 트랙을 `first_track + 최대 후보 수`만큼, **빈 오디오 트랙 1개**를 먼저 만든다 (템플릿 소리가 기존 오디오를 덮지 않게)
- AE로 만든 템플릿: `getMGTComponent()` 속성 값이 JSON, `textEditValue`를 바꿔 setValue. 두 칸(윗줄/아랫줄)이면 나눠 넣기
- 프리미어로 만든 템플릿("그래픽"): 스크립트로 텍스트를 바꾸면 글자가 사라짐 → **바꾸지 않고 기본 문구 그대로**, 보고에 ★로 표시
- 마커 끝은 `m.end = 초(숫자)`
- 도구 추가 (2026-10-11): `replace_ae.jsx`(PR 후보 → 같은 자리 `_AE`판), `swap_template.jsx`(특정 템플릿 클립을 다른 템플릿으로 — 문구·폰트·묶음 길이·끝 시간·이름·마커), `fix_runs.jsx`(글자 묶음 길이 검사·수정)
- AE 템플릿 만들기 (2026-10-12): 애프터이펙트 스크립트는 **반드시 `scripts/point/ae/run_ae.ps1`로** 보낸다 — 프리미어가 띄운 창 없는 AE(`-m`)와 구분, 내보내기 전 저장, 단계별 기록 ([playbook_AE변환.md](playbook_AE변환.md) 9장). 정보형 4종 `_AE`는 원본 폰트 유지(`set_font.jsx` KEEP_FONTS)
- 프리미어 템플릿은 `importMGT`가 오류 없이 **안 들어갈 때가 있음** → 배치 후 반드시 `fill_missing.jsx`(배치.json 기준으로 빠진 후보를 넣고 바로 확인)를 돌려 전부 들어갔는지 확인. 한 번에 많이 넣으면 45초 시간 초과 → `LIMIT`로 나눠서
- 원래 시퀀스에 편집자의 강조 자막(캡션 트랙 등)이 이미 있어도 **그대로 두고 평소대로 배치** (criteria.md). 있으면 완료 보고에 알리기만 한다
