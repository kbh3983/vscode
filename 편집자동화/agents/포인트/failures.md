# 포인트 — 잘 안된 결과 (하지 말 것)

사용자가 불만족한 결과. **같은 실수를 피할 때만** 참고한다. 좋은 방법의 근거로 쓰지 않는다.

형식:
```
## [단계] 제목 (날짜, 프로젝트명)
- 상황:
- 한 방법 / 사용한 값:
- 무엇이 문제였나 (사용자 피드백 원문):
- 하지 말 것:
```

## [P4] 구간당 후보 3~6개 + 같은 스타일 색상 변형을 함께 배치 (2026-10-11, 목교정기_종편_모노_색보정_포인트)
- 상황: 유형별 후보를 "모두" 넣는 규칙대로 배치
- 한 방법 / 사용한 값: 강조 = 강한말 빨강·주황·검정 + 강조말 노랑·하늘 (5개), 화남 6개 등 V9~V14
- 무엇이 문제였나 (사용자 피드백 원문): "포인트 자막 후보는 3개로 제한할게. 그 이상은 검토가 힘들어서." / "동일한 스타일인데 색상만 바뀐 경우 예를 들어 PANDA-강조말-하늘_2016과 노랑을 동시에 사용하지 말아줘. 색상 차이는 너무 작아."
- 하지 말 것: 한 구간에 후보 4개 이상 넣지 않는다. 색상만 다른 같은 스타일(`-노랑`/`-하늘`, `-빨강`/`-주황`/`-검정` 등)을 한 구간에 같이 넣지 않는다

## [AE 변환] AE 스크립트가 반복해서 멈추거나 내보내기 실패 (2026-10-12, 정보형 4종 `_AE`)
- 상황: `make_info4.jsx`를 `AfterFX -r`로 여러 번 실행
- 한 방법 / 사용한 값: 예전 `run_ae.ps1` — "AfterFX 프로세스가 있으면 켜진 것"으로 보고 바로 `-r`. 결과 파일이 생기기만 하면 끝으로 판단. 내보내기 전에 프로젝트 저장 안 함. 멈추면 원인 확인 없이 강제 종료 후 다시 실행
- 무엇이 문제였나 (사용자 피드백 원문): "point_ae_run.jsx 실행중 응답없음이떠" / "왜 계속 작업이 안 되는지 원인 파악 후 알려줘."
  - 실제 원인: 프리미어(dynamiclinkmanager)가 띄운 창 없는 AE(`-m`)를 내 AE로 착각 → AE 두 개가 같이 돌며 내보내기에서 멈춤 / 스크립트가 창 없는 쪽으로 감. 저장 안 된 프로젝트라 내보내기 false. "저절로 다시 켜진 AE"도 사실 프리미어용
- 하지 말 것: `AfterFX -r`을 직접 부르지 않는다(`run_ae.ps1`만). 프로세스 이름만으로 AE가 켜졌다고 판단하지 않는다. 멈춤을 원인 확인 없이 재시도·강제 종료로 넘기지 않는다 — 결과 파일 마지막 줄·CPU·명령줄·부모를 먼저 보고 사용자에게 알린다 (playbook_AE변환.md 9장)

## [시험] 프리미어 `createNewSequence`로 임시 시퀀스 만들다 멈춤 (2026-10-13, 템플릿 교체 확인)
- 상황: 새 `.mogrt`가 프로젝트의 예전 판 대신 쓰이는지 보려고 임시 시퀀스 생성
- 한 방법 / 사용한 값: `app.project.createNewSequence(이름, ID)` — 프리미어에 "새 시퀀스" 설정 창이 떠서 입력을 기다리며 스크립트 45초 시간 초과, 다음 호출도 멈춤 (사용자가 창을 닫아 풀림)
- 무엇이 문제였나: 사용자 화면에 창이 떠 작업을 막음
- 하지 말 것: `createNewSequence`를 쓰지 않는다. 시험용 시퀀스가 필요하면 기존 시퀀스를 `clone()`(복제)하거나, 사용자에게 먼저 묻는다

## [도구] 템플릿 클립을 원래 트랙에 다시 넣다 뒤 클립을 덮어씀 (2026-10-26, 누워서_컷편집_컷전환_포인트_정렬)
- 상황: 폰트 수정 허용을 위해 클립을 지우고 같은 자리에 `importMGT`로 다시 넣는 첫 시도 (`refresh_mgt.jsx` 첫 판)
- 한 방법 / 사용한 값: 원래 클립 remove → 같은 트랙·시간에 importMGT → 끝 시간 줄이기. 8개씩 묶어 실행
- 무엇이 문제였나: importMGT가 템플릿 전체 길이(15초)로 들어가 같은 트랙 뒤 클립을 덮어씀 → V3 클립 4개 사라지고 1개 앞부분 잘림. 1개만 먼저 시험했을 때는 뒤 클립이 없어 안 드러남. 색 칸은 getValue 숫자로 setValue하면 흰색이 됨, 불투명도 "혼합 모드" 두 개를 이름으로 맞추다 섞임
- 고침: 작업 전 백업 복제본이 있어 손상된 시퀀스는 `_작업실패`로 이름 바꿔 두고, 백업을 복제해 원래 이름으로 다시 작업. 새 빈 트랙에 넣고 마지막에 원래 클립·빈 트랙 정리, 색은 getColorValue/setColorValue, 컴포넌트 값은 순서로 짝
- 하지 말 것: 클립이 이어진 트랙에 importMGT로 바로 넣지 않는다. 클립을 지우고 다시 넣는 작업은 **반드시 백업 복제본을 먼저** 만들고, 시험은 뒤에 클립이 있는 자리에서 한다
