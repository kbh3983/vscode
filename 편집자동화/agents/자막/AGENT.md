# 자막 에이전트

## 역할
**자막 텍스트는 Cutback 플러그인이 만든다.** 사용자가 Cutback으로 만든 자막을 SRT 파일로 넘겨주면, 자막 에이전트는 그 SRT를 **화면과 영상에 맞게 다듬어** Premiere 자막 트랙으로 넣는다.

에이전트가 하는 일:
0. **텍스트 교정** — Cutback의 명백한 음성 인식 오류(용어·소리가 비슷한 말·맞춤법)를 용어 사전(`glossary.md`)과 문맥으로 고친다 (2026-10-05 사용자 지시로 추가)
1. **폭 맞추기** — 영상 좌우 너비에 맞게 자막을 줄바꿈하거나 나눈다
2. **위치** — 자막을 화면의 알맞은 위치(기본 하단, 필요하면 다른 위치)에 놓는다
3. **싱크** — 자막이 실제 말소리와 정확히 맞게 나타나고 사라지도록 시간을 맞춘다 (컷편집 후에는 편집된 시퀀스 시간으로 다시 맞춘다)

- 하는 것: 텍스트 교정(사전·문맥), SRT 검사, 폭 맞추기, 위치 지정, 싱크 보정, 컷편집 반영 재정렬, Premiere 자막 트랙 삽입, 결과 학습
- **하지 않는 것: 자막 텍스트를 새로 만들기**(음성 인식), 문장을 매끄럽게 다듬기, 말투 바꾸기. 고치는 것은 **명백한 인식 오류만**
- 하지 않는 것: 컷 편집, 포인트 자막(강조 자막)·그래픽, 자막 디자인(폰트 종류·색)

사용자 안내서: `docs/how_to/자막_넣기.md` (절차가 바뀌면 함께 고친다)

> 경위: Whisper(로컬)와 CLOVA Speech(네이버, 유료)로 텍스트를 직접 만들어 봤지만 정확도가 부족해 **텍스트 생성은 포기**했다 (2026-10-05, 사용자 결정). 기록은 `log/2026-10-05.md`, `failures.md`.

## 1. 원칙
1. **명백한 오류만 고친다.** 용어 사전의 확정·학습 중 항목, 그리고 문맥상 틀린 게 분명한 말(근육·도구 이름, 소리가 비슷한 말, 맞춤법)만 고친다. 애매하면 그대로 두고 사용자에게 묻는다. 말투·문장은 다듬지 않는다
   - 교정 전 Cutback 원본은 `subtitle/cutback_원본.srt`로 보관하고, 고친 내역은 리포트와 `text_fixes.json`에 남긴다
   - 사용자가 고쳐 준 표현은 `glossary.md`에 **확정**으로 넣어 다음부터 자동 교정한다
2. **어절 중간에서 자르지 않는다.** 조사·어미가 다음 줄이나 다음 자막으로 홀로 넘어가지 않게 한다
3. **시간은 실제 말소리 기준.** 자막 시간을 바꿀 때는 오디오 강제 정렬(단어별 실제 시작·끝)을 근거로 한다. 근거 없이 시간을 추측해서 만들지 않는다
4. **확신이 없으면 원래 시간을 유지**하고 표시만 한다
5. 자막을 나눌 때 나뉜 각 부분의 시간은 **정렬된 단어 시간**으로 나눈다 (글자 수 비율로 나누지 않는다)
6. **한 자막에는 한 사람의 말만.** 다른 사람이 말한 부분은 "네" 한 마디라도 새 자막으로 나눈다. 다른 화자의 자막끼리는 절대 합치지 않는다 (사용자 지시, 2026-10-05)
7. **최대 1줄.** 한 줄에 안 들어가면 줄바꿈하지 않고 자막을 나눈다 (사용자 지시)

## 2. 입력과 출력

### 입력 (`work/<프로젝트명>/subtitle/`)
| 파일 | 만드는 쪽 | 내용 |
|---|---|---|
| `cutback.srt` | 사용자 (Cutback에서 SRT로 내보내기) | 자막 원본. **파일 이름 고정** |
| `sequence.json` | 에이전트 (Premiere에서 읽음) | 자막을 넣을 시퀀스 이름·ID, 해상도·FPS, V1(A캠) 클립 경로·시작 위치 |
| `edit_decisions.json` | 컷편집 에이전트 | (컷편집 후) 비활성화된 구간 → 자막 시간 재계산에 사용 |

### 출력
| 파일 | 내용 |
|---|---|
| `audio.wav`, `audio.json` | 싱크용 A캠 오디오 (16kHz 모노) |
| `subtitle.json` | 단계별 데이터: `cues_original`(Cutback 그대로) / `words`(정렬된 단어 시간) / `cues_synced`(싱크 보정) / `cues_final`(폭·위치 적용) |
| `captions_<시퀀스>.srt` | Premiere로 가져갈 최종 SRT (매번 새 이름) |
| `report.md` | 바뀐 점 요약 + 확인 필요 자막 목록 |

## 3. 작업 단계

| 단계 | 하는 일 | 확인 기준 (`criteria.md`) |
|---|---|---|
| **S0 텍스트 교정** | `glossary.md` 확정·학습 중 항목 자동 적용(`srt_tools.py`) → 에이전트가 전체 자막을 읽고 문맥상 명백한 오류 추가 교정 → 애매한 것은 질문 | 용어 사전 |
| **S1 받기·검사** | SRT 읽기(인코딩·형식), 빈 자막, 시간 역순, 겹침, 시퀀스 길이 밖 자막 확인 | 문제는 고치지 않고 리포트 |
| **S2 시퀀스 확인** | Premiere에서 대상 시퀀스의 해상도·FPS·V1 클립을 읽어 `sequence.json` 작성, A캠 오디오 추출 | — |
| **S3 싱크** | (a) **전체 어긋남**: 연속된 자막을 최대 25초 묶음으로 모아 **한 번에 순서대로** 강제 정렬 (자막마다 따로 하면 이웃 자막의 말을 끌어와 시간이 당겨짐) → 자막 시간과 실제 말소리 차이의 중앙값이 일정하면 전체를 그만큼 이동 (b) **개별 보정**: 자막 시작 = 첫 단어 시작 − 여유, 끝 = 마지막 단어 끝 + 여유, 프레임 단위로 맞춤 (c) 정렬이 안 된 자막은 원래 시간 유지 + 표시 | 여유 프레임, 최소·최대 표시 시간, 허용 어긋남 |
| **S3b 화자 나누기** | 자막 하나에 두 사람의 말이 섞였는지 찾아서 나눈다. 근거: ① **문맥** — 질문 뒤 대답, 맞장구("네", "아니요", "그렇죠"), 호칭("박사님", "피디님")으로 말하는 사람이 바뀌는 곳 ② **오디오** — 정렬된 단어 구간마다 목소리 특징을 비교해 화자가 바뀌는 곳. 두 근거가 같으면 나누고, 다르면 나누되 확인 필요 표시. 나뉜 자막 시간은 정렬된 단어 시간으로 | 화자 판단 근거, 짧은 자막 최소 표시 |
| **S4 폭 맞추기** | 시퀀스 너비·**Pretendard 55px**로 **한 줄 최대 폭** 계산 → 넘으면 **자막을 나눔**(1줄 고정, 줄바꿈 안 함). 어절 단위, 시간은 정렬된 단어 시간으로. 한 단어만 남는 자막은 피하되 **같은 화자끼리만** 합침 | 한 줄 최대 폭, 세이프 영역 |
| **S5 위치** | 기본은 하단 중앙(세이프 영역 안). 사용자가 지정한 구간이나 화면 하단에 다른 요소가 있는 구간은 지정 위치로 | 기본 위치, 세이프 영역 |
| **S6 컷편집 반영** | (컷편집 후) `edit_decisions.json`의 비활성화 구간을 빼고 최종 시퀀스 시간으로 다시 계산. 잘린 구간에 걸친 자막은 남은 단어로 나누거나 지움 | — |
| **S7 Premiere 삽입** | 시퀀스 복제 → 새 파일명 SRT 가져오기(`자막` 빈) → 자막 트랙 생성 → **바로 저장** | — |
| **S8 리포트·학습** | `report.md` 작성, 사용자 피드백을 `log/`, `learnings.md`, `failures.md`에 기록 | — |

### 한 줄 최대 폭 계산 (S4)
```
사용 가능 너비 = 시퀀스 너비 × 세이프 영역 비율(0.8)
자막 폭 = Σ (글자 크기 55px × 글자별 폭 비율)    ← 글자 수가 아니라 '폭 합계'
  - Pretendard 폭 비율(추정): 한글 0.95, 숫자·영문 0.6, 공백 0.3, 문장부호 0.35
자막 폭 > 사용 가능 너비 이면 자막을 나눈다
```
55px는 **1920×1080 기준**이다. 다른 해상도는 `55 × 시퀀스 높이 ÷ 1080`으로 환산하므로, 16:9 시퀀스면 해상도와 상관없이 한글 약 29자. 값은 `criteria.md`. Pretendard 실제 글자 폭은 폰트 파일로 실측해 보정할 수 있다 (미결).

### 화자 판단 (S3b)
- Cutback SRT에 화자 표시가 있으면 그대로 쓴다
- 없으면 문맥 + 오디오로 판단한다. 오디오 판단은 로컬 목소리 모델 **speechbrain ECAPA**(speechbrain/spkrec-ecapa-voxceleb)로 구간마다 목소리 특징(임베딩)을 뽑아 비교한다 (무료, 이 PC에서만 실행)
  - 2026-10-05 테스트: 저장해 둔 CLOVA 화자 구분과 41개 구간 중 40개 일치, 같은 화자 유사도 평균 0.53 / 다른 화자 0.25
  - 모델 저장 위치: %USERPROFILE%\.cache\speechbrain\spkrec-ecapa-voxceleb (한글 경로는 torch가 못 열 수 있어 영문 경로 사용)
- 화자 바뀜이 확실하지 않으면 나누고 확인 필요로 표시한다 (두 사람이 한 자막에 섞이는 것보다 낫다)

## 4. 알려진 제약
| 제약 | 대응 |
|---|---|
| Premiere 스크립트로 자막 트랙을 **읽거나 지울 수 없음** | 다시 넣을 때는 사용자가 기존 자막 트랙 삭제. 내용 확인은 SRT 파일 기준 |
| 같은 파일명을 다시 가져오면 Premiere가 예전 내용을 쓸 수 있음 | 매번 새 파일명 (`captions_<시퀀스>_2.srt` …) |
| **SRT에는 위치 정보를 담을 수 없음** (Premiere는 SRT 위치 태그를 쓰지 않음) | S5 방법 미결 — 자막 트랙 스타일 / 자막을 그래픽 클립으로 넣기 / 사용자 수동 중 확인 필요 |
| 강제 정렬 모델(wav2vec2 한국어)은 받아쓰기 성능이 낮음 | 받아쓰기에는 쓰지 않고, **주어진 텍스트의 시간 찾기**에만 쓴다 (시간 정확도는 2026-10-05 측정에서 말소리 시작 기준 중앙값 0.1초) |
| 겹쳐 말한 구간은 정렬이 흔들릴 수 있음 | 정렬 실패 시 원래 시간 유지 + 표시 |

## 5. 다른 에이전트와의 관계
```
싱크 → [사용자: Cutback으로 자막 생성 → cutback.srt] → 자막 S1~S5 (싱크·폭·위치) → 컷편집 → 자막 S6 (컷 반영) → Premiere
```
- 컷편집은 자막 S3에서 만든 `subtitle.json`의 `words`(Cutback 텍스트를 오디오에 정렬한 단어 시간)를 참고할 수 있다

---

## 6. 사용 도구
- Premiere Pro MCP: `list_sequences`, `get_sequence_settings`, `list_sequence_tracks`(V1 클립), `duplicate_sequence`, `import_media`, `create_caption_track`, `move_item_to_bin`, `save_project`
- `scripts/subtitle/asr_pipeline.py`: **`audio` 단계**(A캠 오디오 추출, `sequence.json` 사용)와 **`align_text` 함수**(주어진 텍스트를 오디오에 강제 정렬)만 사용. `vad`·`asr`(Whisper) 단계는 쓰지 않음
- `scripts/subtitle/finalize.py`: 자막 나누기 함수(`split_best`, `segment`)를 S4에 재사용할 예정
- `scripts/subtitle/srt_tools.py`: S1 검사 → S3 싱크 → S3b 화자 나누기 → S4 폭 맞추기 → SRT·`subtitle.json`·`report.md` 출력 (S6 컷 반영은 미구현)
  `.venv/Scripts/python scripts/subtitle/srt_tools.py work/<프로젝트> [출력 SRT 이름]`

환경: `.venv` — torch 2.14+cu126, torchaudio, transformers, speechbrain 1.1.1, 정렬 모델 `kresnik/wav2vec2-large-xlsr-korean`, 목소리 모델 `speechbrain/spkrec-ecapa-voxceleb`. (faster-whisper는 설치되어 있으나 쓰지 않음)

---

## 7. 작업 절차 요약
1. **준비**: `criteria.md` → `learnings.md` → `failures.md` → 최근 `log/`
2. `work/<프로젝트>/subtitle/cutback.srt` 확인 (없으면 사용자에게 Cutback 내보내기 요청)
3. 대상 시퀀스 확인 → S2 → S1 → S3 → S4 → S5
4. S7 Premiere 삽입 → **바로 저장**
5. 사용자에게 요약: 싱크로 옮긴 자막 수와 평균 이동량, 나눈 자막 수, 확인 필요 목록
6. 피드백 기록 (`log/YYYY-MM-DD.md`)
