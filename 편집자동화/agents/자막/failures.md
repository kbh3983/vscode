# 자막 — 잘 안된 결과 (하지 말 것)

사용자가 불만족한 결과. **같은 실수를 피할 때만** 참고한다. 좋은 방법의 근거로 쓰지 않는다.

형식:
```
## [단계] 제목 (날짜, 프로젝트명)
- 상황:
- 한 방법 / 사용한 값:
- 무엇이 문제였나 (사용자 피드백 원문):
- 하지 말 것:
```

## [텍스트 생성] 음성 인식으로 자막 텍스트를 직접 만듦 (2026-10-05, 최박사_운동법_테스트)
- 상황: 카메라 내장 마이크, 압축 사본 오디오(720p 3.3Mbps), 앞부분은 여러 사람이 겹쳐 말하는 촬영 전 대화
- 한 방법 / 사용한 값: Premiere 전사 → 로컬 Whisper large-v3(+강제 정렬, 문맥 교정, 재인식 후보) → 네이버 CLOVA Speech(유료, 키워드 부스팅·화자 구분)
- 무엇이 문제였나 (사용자 피드백 원문): "정확도가 너무너무 떨어지잖아!! Whisper 못쓸거같아" / "이게 무슨 유료서비스야 … 정확도 개구리잖아"
- 하지 말 것:
  - 자막 텍스트를 직접 만들거나 고치지 않는다 (텍스트는 Cutback 플러그인 담당)
  - 유료 서비스를 권하기 전에 **원본 오디오로 무료 비교부터** 한다. 엔진 문제인지 오디오 문제인지 먼저 확인
  - "가장 정확하다"처럼 확인하지 않은 단정을 하지 않는다

## [T5·T6] 애매한 항목을 전부 사용자 검토로 보냄 (2026-10-05, 최박사_운동법_테스트_2)
- 상황: 6분 25초 영상, Premiere 전사 117문장
- 한 방법 / 사용한 값: 문맥상 어색한 곳·신뢰도 낮은 곳을 모두 표로 만들어 사용자에게 정답을 요청 (꼭 확인 38 + 참고 15)
- 무엇이 문제였나 (사용자 피드백 원문): "검토를 다 할수는 없어"
- 하지 말 것: 사용자에게 긴 사전 검토 목록을 넘기지 않는다. 꼭 필요한 것만 짧게 묻는다
