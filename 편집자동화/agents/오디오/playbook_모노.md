**트리거**: 사용자가 "모노" 또는 "모노 사운드"라고 하면 이 절차를 따른다.
**승인**: 2026-10-09, 260929_최박사_운동법3 / `목교정기_종편` → `목교정기_종편_오디오_30초` — 사용자 "결과가 너무좋다. 지금 이 방식을 학습하자."
**전체 적용 승인**: 2026-10-09, `목교정기_종편` → `목교정기_종편_모노` (왼쪽 100% : 오른쪽 77%, 게인 +7.40 dB) — 사용자 "아주좋아. 학습해."

**진행 순서**: 처음 10초 시험 시퀀스(`<시퀀스>_모노_10초`) → 사용자 확인 → 전체(`<시퀀스>_모노`). 전체 때는 비율·게인을 전체 구간으로 다시 계산
- 사용자가 "전체", "_모노로" 처럼 바로 전체를 지시하면 10초 시험 없이 `<시퀀스>_모노`로 진행 (2026-10-09, 열린 4개 시퀀스 일괄)

**스크립트 (여러 시퀀스 일괄)** — 승인 2026-10-09, 열린 4개 시퀀스 일괄 처리: 사용자 "작업 잘 됐어, 결과물 깔끔하다. 학습해줘"
1. ExtendScript로 시퀀스 오디오 트랙·클립 목록을 `work/모노/<시퀀스>.json`에 저장 (`{name,id,end,tracks:[[{clip_id,start,end,in,path,disabled,fx}]]}`)
2. `.venv/Scripts/python scripts/audio/mono.py work/모노/<시퀀스>.json` → 원본 파일마다 두 마이크 확인(엔딩 영상 등 자동 제외), 비율·게인 계산 → `<시퀀스>_plan.json`
3. 원본 복제 → `<시퀀스>_모노`
4. `execute_extendscript`: `var SEQ_ID="<새 ID>"; var PLAN="<plan 경로>"; var MONO_RESULT=""; $.evalFile(".../scripts/audio/apply_mono.jsx"); return MONO_RESULT;` (다른 카메라 음성 트랙 음소거 + 이펙트 추가·설정)
5. 전체 WAV 내보내기 → `.venv/Scripts/python scripts/audio/mono_verify.py work/모노/<시퀀스>.json <결과.wav>`
- 한 영상의 C캠이 파일 두 개로 나뉠 수 있음 (옆구리살: C0027 + C0028) → 가장 많은 파일만 고르지 말고 파일마다 두 마이크인지 확인

## 1. 상황 (사용자 설명 원문 요약)
- 오디오가 A1, A2 트랙으로 나뉘어 있고 등장인물은 두 명
- **A1만 실제로 쓰는 음성.** A2는 영상에서 쓰지 않지만 **오디오 기준 싱크용으로 남겨 둔 것**
- A1은 두 출연자에게 마이크를 하나씩 달아 녹음 → 왼쪽·오른쪽 채널 모두 두 사람 목소리가 들리지만(같은 공간), **왼쪽은 한 사람이, 오른쪽은 다른 사람이 크다**

## 2. 원하는 결과
- **좌우 데시벨이 같고**, 왼쪽 귀·오른쪽 귀 모두 **두 사람 목소리가 같은 크기로 똑같이** 들린다

## 3. 작업 규칙 (사용자 지정)
| 규칙 | 내용 |
|---|---|
| 먼저 일부만 | 시퀀스의 **처음 10초만** 먼저 작업해서 **별도의 시퀀스**로 만든다 (승인 후 나머지) |
| 원본 보호 | 현재 시퀀스는 **아무것도 건드리지 않는다** (읽기만, 복제해서 작업) |
| 작업 대상 | 사용자가 A1에 수음된 작업 파일을 올려 둔다. **A1만** 작업한다 |
| 다른 트랙 | 다른 트랙의 음성은 **음소거만 하고 지우지 않는다** (싱크에 필요). **효과음 트랙은 음소거하지 않는다** |

## 4. 절차

### 4-1. 대상 확인 (먼저 반드시)
1. 사용자가 말한 시퀀스 이름을 프로젝트에서 찾는다. **열려 있는 시퀀스가 대상이라고 가정하지 않는다** (2026-10-09에 열려 있던 `자세교정_종편`으로 잘못 시작했음)
2. A1 클립의 원본 파일·사용 구간(in)·기존 이펙트를 읽는다
3. ffmpeg로 A1 원본의 좌·우를 따로 읽어 확인한다 (50 ms 단위 음량):
   - 좌우 상관이 낮고(≈0), 말할 때 한쪽이 약 10 dB 큰 구간이 번갈아 나오면 → 이 작업이 맞음
   - 좌우가 거의 같으면(차이 < 1 dB) → 카메라 내장 마이크일 수 있음. **진행하지 말고 사용자에게 확인**

### 4-2. 섞는 비율 계산
- 말하는 사람 구분: 좌우 차이 > +4 dB = 왼쪽 마이크 주인, < −4 dB = 오른쪽 마이크 주인
- 후보 비율 a·L + b·R 에서 두 사람 구간의 피크(상위 1% 제외)가 같아지는 b/a를 찾는다
  - 2026-10-09: **1:1에서 차이 0.03 dB** → 비율 보정 없이 L+R
  - 두 사람 차이가 크면 채널 혼합기의 교차 값으로 비율을 맞춘다 (큰 쪽을 줄임, 최대 +100%)
  - **비율은 작업 범위 전체로 계산한다.** 10초·30초에는 한 사람만 말할 수 있다 (목교정기: 30초 기준 0.03 dB → 전체 기준 1.94 dB 차이, 왼쪽 100% : 오른쪽 77%로 맞춤 — 교차값 0.885)
- A1에 다른 소스(예: `롱폼_엔딩영상.mp4`)가 섞여 있으면 두 마이크 녹음 클립(같은 원본 파일)에만 적용한다
- 게인 = 섞은 소리의 말 구간 피크 중앙값을 **−5 dB**로 올리는 값 (2026-10-09: −9.38 → **+4.38 dB**)

### 4-3. 새 시퀀스
1. 원본 시퀀스 복제 → `<시퀀스>_모노_10초` (승인 후 전체는 `<시퀀스>_모노`)
2. 10초에서 모든 트랙 razor (QE `razor`, 29.97 드롭프레임 타임코드 — `scripts/cut/ops.py`의 `df_tc`), 이후 클립·마커 지우기
   - 자막(캡션) 트랙은 스크립트로 못 지움 → 시퀀스 끝이 길게 남으면 사용자에게 알림
3. **A1 외 음성 트랙은 음소거** (QE `getAudioTrackAt(i).setMute(true)`), 지우지 않음
   - **효과음 트랙은 음소거하지 않는다** (사용자 지정, 2026-10-09)

### 4-4. A1 클립 이펙트 (모든 A1 클립 같은 값)
1. 기존 `선택적 제한`, `좌측과 우측 채우기`/`우측과 좌측 채우기`가 있으면 **바이패스** (지울 수 없음)
2. QE로 한 번에 추가: `item.addAudioEffect(qe.project.getAudioEffectByName("채널 혼합기"))`, 이어서 `"선택적 제한"` (이 순서 = 섞은 뒤 제한)
3. **채널 혼합기**: 값 = 0.5 + 퍼센트/200 (0.5 = 0%, 1 = +100%)
   - `[2] L에서 L까지 = 1`, `[3] R에서 L까지 = 1`, `[10] L에서 R까지 = 1`, `[11] R에서 R까지 = 1` → 양쪽 출력 = L+R
4. **선택적 제한(새로 추가한 것)**: `[1] 최대 진폭 = 0.94` (−6 dB), `[2] 입력 증폭 = (게인 dB + 40) / 60` (+4.38 dB → 0.7397)
5. 저장
- ExtendScript는 ES3: `Array.map`·`forEach` 등을 쓰면 스크립트 전체가 실패한다. 이펙트 추가와 값 설정을 나눠 실행하면 실패해도 이펙트가 두 번 들어가지 않는다

### 4-5. 검증 (내보낸 WAV)
- `Waveform Audio 48kHz 16-bit.epr`로 전체 내보내기
- 확인 항목 (2026-10-09 결과):
  | 항목 | 기준 | 결과 |
  |---|---|---|
  | 좌·우 RMS | 같음 | −18.13 / −18.13 dB |
  | 두 사람 구간 미터 최고값 중앙값 | −6 dB 근처, 서로 같음 | −6.00 / −6.00 dB |
  | 두 사람 상위 1% 제외 중앙값 차이 | 1 dB 이내 | 0.5 dB |
  | −6 dB를 넘는 곳 | 효과음 등 다른 트랙만 | 효과음 위치뿐 |
