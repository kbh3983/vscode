# 오디오 — 잘 안된 결과 (하지 말 것)

사용자가 불만족한 결과. **같은 실수를 피할 때만** 참고한다. 좋은 방법의 근거로 쓰지 않는다.

형식:
```
## [단계] 제목 (날짜, 프로젝트명)
- 상황:
- 한 방법 / 사용한 값:
- 무엇이 문제였나 (사용자 피드백 원문):
- 하지 말 것:
```

## [A6 검증] 리미터 후 결과를 게인 계산용 지표로 재서 "작다"로 잘못 판정 → 불필요한 게인 변경 (2026-10-21, 노년 필수근육_…_포인트_정렬)
- 상황: 10/20 오디오(+4.50 dB) 뒤 편집이 바뀌어 다시 확인. 결과 WAV를 내보내 검증
- 한 방법 / 사용한 값: 검증 도구(mono_verify) 대신 즉석 코드로 levels.peak_db(구간 **상위 1% 제외** 최고값)를 결과 WAV에 씀 → 중앙값 -8.05 dB, 범위 0% → "기준보다 작다, +7.55 dB 필요"로 보고 → 사용자 결정으로 `…_포인트_정렬_오디오`에 +7.55 dB 적용 → 0.37 dB만 올라 이상함을 알고 다시 확인
- 실제: 판정 지표는 **구간 최댓값(미터 최고값)** → 원래 -6.00 dB, 103/103(100%) 범위 안. 10/20 검증을 통과한 예전 WAV도 상위 1% 제외로 재면 -8.06 dB로 똑같음 = 편집 변경과 무관한 측정 실수
- 무엇이 문제였나 (사용자: "잘못한 부분은 복기 확실하게 해서, 추후 동일한 일이 벌어지지 않도록 꼭 유의해" (2026-10-21)):
  1. 검증 자리에 게인 계산용 지표를 씀 — 리미터(-6 dB)가 위를 누르면 상위 1% 제외 값은 약 2 dB 낮게 나옴
  2. 기준 문서가 두 지표(게인 계산 / 결과 검증)를 구분하지 않았음
  3. 리미터를 거친 결과 소리로 게인을 다시 계산함 (게인은 리미터 전 원음으로만)
  4. 이전 검증(100%)과 정반대(0%)인데 측정 방법을 의심하지 않고 "버전이 바뀌어서"로 단정 (그럴듯한 설명에 기댐)
  5. 조치(새 시퀀스·게인 변경) 전에 같은 방법으로 이전 결과를 다시 재 보지 않음
- 하지 말 것:
  - 결과 판정을 즉석 코드로 하지 않는다 → **`scripts/audio/check_export.py`로만** (판정 = 미터 최고값, 상위 1% 제외는 참고 출력)
  - 리미터 후 소리(내보낸 WAV)로 게인을 계산하지 않는다 → 게인은 `levels.py`(트랙 원음 합)로만
  - 이전 결과와 크게 다르면(범위 안 비율 30%p 넘게) **같은 도구로 이전 결과도 다시 재서** 방법·대상부터 확인하고, 원인을 확인하기 전에는 결론·조치·제안하지 않는다 (`check_export.py <결과> <이전 결과>`가 경고)
  - 사용자에게 수치로 보고할 때 **어떤 지표로 쟀는지** 같이 적는다

## [최종 점검] 효과음 크기를 전체 믹스 최고값으로 재서 "기준보다 6 dB 크다"로 잘못 보고 (2026-10-26, 노년 필수근육_…_정렬_오디오)
- 상황: 출력 전 최종 점검. 13.01 '뿅'(사용자 교체, 클립 볼륨 0 dB)
- 한 방법: 전체 믹스 WAV의 13초 구간 최고값 −5.17 dB + 파일 피크(−2.05)·모노 팬 −3 dB 추정으로 "뿅이 약 −5 dB, 기준보다 6 dB 큼"이라고 보고 → 사용자가 볼륨을 내림
- 실제: A4를 끈 믹스를 빼서 효과음만 재 보니 뿅은 **−9.99 dB(기준 −10~−12 안)**. −5.17은 같은 순간의 **말소리(−6.0)와 합친 값**. 사용자가 내린 뒤 −15.99 dB(기준 아래)
  - 같은 방법으로 띠링(2870)은 −13.57 dB — 넣을 때 계산(−11)보다 2.6 dB 작음 (파일 피크 계산이 실제 출력과 다름)
- 하지 말 것:
  - 효과음·배경음악 크기를 **믹스 구간 최고값으로 판정하지 않는다** → 그 트랙만 끈 내보내기를 빼서(또는 그 트랙만 켠 내보내기로) 따로 잰다
  - 파일 피크 + 볼륨 계산값을 결과처럼 보고하지 않는다 — "계산값"으로 표시하고, 판정은 내보낸 소리로
  - 값을 추정(모노 팬 −3 dB 등)으로 맞춰 설명하지 않는다 (2026-10-21 "그럴듯한 설명에 기댐"과 같은 실수)

## [배경음악 배치] 클립 끝(end)만 바꾸고 out 점을 그대로 둬서 길이를 늘릴 수 없었음 (2026-10-26, 스틱 뜀뛰기 _1920_오디오 · 노년 _정렬_오디오)
- 상황: `overwriteClip`으로 곡을 넣고 `clip.end`만 구간 끝으로 줄임 → 타임라인 길이 59.5초인데 `outPoint`는 곡 끝(174~239초) 그대로
- 결과: 사용자 "5개 음악 모두 길이 수정할 수 있게 수정해줘." — 끝을 끌어 늘릴 수 없었음. 노년 배경음악 3개도 같은 상태(확인만, 출력 끝난 시퀀스라 안 고침)
- 하지 말 것: 클립을 넣고 길이를 바꿀 때 `end`만 바꾸지 않는다 → **`outPoint = inPoint + (end − start)`도 같이 맞춘다** (포인트 refresh_mgt.jsx와 같은 원리, 2026-10-26)

## [검증] 일부 구간만 내보내려다 In 점이 안 먹어 다른 구간을 잼 (2026-10-27, 근감소증 엔딩 앞 여유)
- 상황: 끝부분(770~780초)만 확인하려고 `seq.setInPoint(770); seq.setOutPoint(780)` 뒤 `exportAsMediaDirect(…, 0)` → In 점이 적용되지 않아 처음 10초가 내보내짐. 음량만 보고 넘어갈 뻔했고, 받아쓰기 결과가 인트로 문장이라 알아챔
- 하지 말 것: 구간 내보내기 결과를 그대로 믿지 않는다. 내보낸 뒤 `getInPointAsTime()/getOutPointAsTime()`과 파일 길이로 구간이 맞는지 확인하거나(`scripts/color/export_frames.jsx`처럼), **전체를 내보내 ffmpeg `-ss`로 잘라서** 잰다
