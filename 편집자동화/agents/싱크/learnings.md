## [S4·S5·S6] 2캠 오디오 싱크 첫 성공 (2026-10-04, 최박사_운동법_테스트)
- 상황: 카메라 2대, 클립 각 약 5분 30초, 1280x720 29.97fps, 카메라 내장 오디오(AAC 48k), 메타데이터로 카메라 구분 불가
- 한 방법 / 사용한 값:
  - 대략 위치: 2kHz 모노 전체 비교, **GCC-PHAT** (단순 파형 비교는 신뢰도 0.39로 부족 → PHAT 0.90)
  - 정밀 위치: 16kHz, 음성 대역 100~4000Hz, PHAT-β 0.7, **겹치는 구간 전체를 20초씩 나눠 계산한 값의 중앙값**
  - 결과를 프레임 단위로 반올림해 배치 (C0017 = +215프레임)
  - 시퀀스: 클립 설정과 같은 프리셋(AVCHD 720p30)으로 생성 후 V1/A1 기준, V2/A2 보조
- 사용자 피드백 (원문): "좋아"
- 다음에 적용할 점: 같은 계산 방식(scripts/sync/offsets.py)을 기본으로 쓴다. 구간 하나의 결과만 믿지 않는다.

## [S2·S4·S5·S10] playbook 그대로 두 번째 싱크 성공 (2026-10-04, 최박사_운동법_테스트 / 둔근 운동법 원본)
- 상황: 카메라 2대, 클립 각 약 6분 25초, **3840x2160 29.97fps, PCM 48k**, 원본 폴더 이름 cam 1/cam 2가 A/B와 반대
- 한 방법 / 사용한 값:
  - A캠 판단: ffmpeg로 2분 지점 프레임 캡처(640px) → 정면·넓은 샷 = C0020-002(A), 측면·가까운 샷 = C0018-004(B). **폴더 이름 무시**
  - 오프셋: offsets.py 기본값 그대로 → +30프레임, 신뢰도 0.89, 편차 0.98, 드리프트 0.05
  - 라벨을 배치 전에 지정 (A=1, B=0) → 재배치 없이 한 번에 맞음
  - 시퀀스 프리셋: `UHD (4K)\UHD (4K) 2160p 29.97 fps.sqpreset`
- 사용자 피드백 (원문): "A캠 잘 맞았어. 싱크도 잘 맞아! 학습해."
- 다음에 적용할 점: playbook.md 순서를 그대로 따른다. 4K 29.97 클립은 위 프리셋을 쓴다. 구간 편차가 1프레임에 가까워도(0.98) 실제 싱크는 정상이었다.
