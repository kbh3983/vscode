# 싱크 — 잘 안된 결과 (하지 말 것)

사용자가 불만족한 결과. **같은 실수를 피할 때만** 참고한다. 좋은 방법의 근거로 쓰지 않는다.

형식:
```
## [태스크ID] 제목 (날짜, 프로젝트명)
- 상황 (카메라 구성, 촬영 길이 등):
- 한 방법 / 사용한 값:
- 무엇이 문제였나 (사용자 피드백 원문):
- 하지 말 것:
```

## [S10] 라벨 색 번호를 영어 이름으로 짐작 (2026-10-04, 최박사_운동법_테스트)
- 상황: B캠을 '보라'로 지정해 달라는 요청
- 한 방법 / 사용한 값: MCP 도구 설명의 "8=Purple"을 보라로 보고 index 8 적용
- 무엇이 문제였나 (사용자 피드백 원문): "한국어 버전 기준 '보라'가 아닌 '자주색'으로 변경 되어있어"
- 하지 말 것: 영어 색 이름으로 한글 라벨을 짐작하지 않는다. `agents/README.md`의 라벨 번호표(Prefs 파일 기준)를 쓴다. 보라 = 0

## [S10] 배치 후에 빈 라벨만 변경 (2026-10-04, 최박사_운동법_테스트)
- 상황: 시퀀스 배치를 끝낸 뒤 B캠 라벨 변경
- 한 방법 / 사용한 값: 촬영본 빈의 클립 라벨만 변경
- 무엇이 문제였나 (사용자 피드백 원문): "v01_sync 폴더에 v2와 a2 색상이 보라로 바뀌지 않았어"
- 하지 말 것: 배치 후 빈 라벨만 바꾸고 끝내지 않는다. 라벨은 배치(S5) 전에 지정한다

## [S5·S10] 새 시퀀스에 클립을 다시 올려 원본 라벨이 바뀜 (2026-10-19, 260929_최박사_운동법4 / 누워서 하는 최고의 서킷트레이닝)
- 상황: 사용자가 만든 원본 시퀀스(누워서_원본)에 카메라 2대·테이크 2개가 올라가 있고, 클립마다 라벨로 캠을 구분해 둔 상태. "오디오 싱크만" 요청
- 한 방법 / 사용한 값: 새 시퀀스 v01_sync를 만들고 `add_to_timeline`으로 프로젝트 아이템을 다시 올림 → 클립 라벨이 프로젝트 아이템 라벨(창포색 1)로 모두 바뀜
- 무엇이 문제였나 (사용자 피드백 원문): "올기면서 레이블 색상이 변경됐어. 그건 원본 그대로 유지해야 돼, 캠을 나누는 기준이거든."
- 하지 말 것: 원본 시퀀스가 있을 때 클립을 새로 올리지 않는다. 원본 시퀀스를 복제(duplicate_sequence)하고 클립 위치만 옮긴다 (playbook 6-B)

## [원본 시퀀스 만들기] 사용자가 세팅한 시퀀스를 확인 없이 비움 (2026-10-26, 261013_최박사_라이브 / 체어 웨이트볼 고관절_원본)
- 상황: 4편 원본 시퀀스를 터틀볼 형식(V1 B캠·V2 A캠·A1 A캠 소리·A2 B캠 소리, B캠 보라)으로 다시 놓는 중. 시험용으로 고른 체어 웨이트볼 시퀀스를 사용자가 그 사이 직접 세팅해 둠("체어 웨이트볼도 그렇게 세팅해뒀어") → 제가 클립을 모두 지움 ("내가 세팅한 걸 지웠네")
- 무엇이 문제였나: 몇 분 전 읽은 상태를 믿고, 지우기 직전에 다시 읽지 않음. 사용자가 같은 프로젝트에서 동시에 작업 중이었음(터틀볼도 그 사이 바뀌어 있었는데 신호로 받아들이지 않음)
- 하지 말 것:
  - 클립을 지우거나 덮어쓰기 **직전에** 그 시퀀스를 다시 읽고, 처음 읽은 상태와 다르면 멈추고 묻는다
  - 사용자가 같은 프로젝트를 만지고 있다는 신호(읽은 상태가 바뀜, 중간 메시지)가 있으면 지우는 작업 전에 대상 시퀀스를 확인받는다
  - 시험은 임시 시퀀스에서 한다
- 참고(기술): 스크립트·MCP로 클립을 넣으면 영상 트랙 k ↔ 오디오 트랙 k가 늘 같은 원본으로 들어감(`overwriteClip`, `add_to_timeline`, `replace_clip`, `move_clip_to_track` 모두 — 이동은 짝 클립을 같은 번호 트랙에 1.001초 밀려 하나 더 만듦). 그래서 V1 B캠 + A1 A캠처럼 같은 번호에 다른 카메라를 두는 배치는 그대로는 못 만듦
