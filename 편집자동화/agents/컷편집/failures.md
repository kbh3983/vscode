# 컷편집 — 잘 안된 결과 (하지 말 것)

사용자가 불만족한 결과. **같은 실수를 피할 때만** 참고한다. 좋은 방법의 근거로 쓰지 않는다.

형식:
```
## [태스크ID] 제목 (날짜, 영상명)
- 상황:
- 한 방법 / 사용한 값:
- 무엇이 문제였나 (사용자 피드백 원문):
- 하지 말 것:
```

---

## [C1] 운동 동작 중 무음을 자름 (2026-10-06, 261006_최박사_운동법_AI / 옆구리살_가편_오디오2)
- 상황: 운동 1에서 "엉덩이 살짝 들어 올려 볼까요"(212초)부터 동작이 시작됐는데, 숫자를 세기 시작한 259초부터만 "반복 동작 구간"으로 보고 그 앞 무음을 잘랐다
- 한 방법 / 사용한 값: 무음 −40 dB·0.7초 이상 → 0.3초 남김, 232~258초에서 6곳 삭제
- 무엇이 문제였나 (사용자 피드백 원문): "운동중 무음구간이라서 이컷은 컷편집이 되면 안돼" (6곳)
- 하지 말 것: 운동 동작이 **시작된 순간**(동작 안내: "들어 올려", "넘기는 겁니다", "이 상태에서 … 당겨" 등)부터 그 운동의 세트가 끝날 때까지 무음을 자르지 않는다. 숫자 세기 시작을 기준으로 삼지 않는다

## [C5] 정렬 단어 시간만 믿고 말더듬을 잘라 앞 단어 끝이 잘림 (2026-10-06, 같은 영상)
- 상황: "시원한 느낌 / 많이 많이 굳어 있으면"에서 앞 "많이"를 지움. 정렬 모델이 앞 "많이"를 328.42~328.50초(0.08초)로 잘못 잡았고, 실제로는 328.6~329.1초
- 한 방법 / 사용한 값: 자막 시작 시간(328.36초)부터 다음 "많이" 시작 −2프레임까지 삭제 → "느낌" 끝이 잘림
- 무엇이 문제였나 (사용자 피드백 원문): "많이, 많이 이 두가지 말을 중복해서 하는것 때문에 자른거같아. 앞에 시원한느낌까지는 컷편집되면 안돼."
- 하지 말 것: 단어 단위 컷(C4·C5·C8)을 정렬 시간 그대로 자르지 않는다. 0.1초 안팎으로 짧게 정렬된 단어는 특히 믿지 않는다. 컷 경계마다 **실제 오디오의 쉼**(주변보다 6 dB 이상 조용한 지점, ±0.15초 안)을 찾아 맞추고, 쉼이 없으면 자르지 않고 review로 둔다 (`scripts/cut/plan.py`의 `snap_to_dip`)
