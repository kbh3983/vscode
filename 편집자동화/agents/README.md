# 에이전트 공통 구조

각 에이전트는 `agents/<이름>/` 폴더 하나를 가진다.

```
agents/<이름>/
├── AGENT.md       역할, 담당 태스크, 작업 절차, 입출력 (에이전트의 "직무 기술서")
├── playbook.md    승인된 작업을 그대로 재현하는 실행 절차서 (도구 호출·명령·값). 승인된 결과가 생기면 만든다
├── criteria.md    현재 적용 중인 기준값·규칙 (승인된 것만 반영)
├── learnings.md   사용자가 승인한 좋은 결과와 그 방법
├── failures.md    사용자가 불만족한 결과 ("하지 말 것" 목록)
└── log/
    ├── _template.md
    └── YYYY-MM-DD.md   날짜별 작업 기록
```

## 작업 시작 전 (모든 에이전트 공통)
1. `AGENT.md` → `playbook.md`(있으면) → `criteria.md` → `learnings.md` → `failures.md` 순서로 읽는다.
2. `log/`에서 가장 최근 기록 1~2개를 읽어 이어지는 맥락을 파악한다.

## 학습 규칙
| 사용자 반응 | 기록 위치 | 다음 작업에 반영 |
|---|---|---|
| 명시적 승인 ("좋아", "이걸로 가자") | `log/` + `learnings.md` (+ 재현할 절차는 `playbook.md`) | ✅ 따라 한다 |
| 불만족·수정 요청 | `log/` + `failures.md` | ⛔ 반복하지 않는다 |
| 반응 없음 / 애매함 | `log/`에만 "보류"로 기록 | ❌ 반영하지 않는다. 다음에 사용자에게 확인한다 |

- `criteria.md`의 기준값은 **사용자가 승인한 경우에만** 바꾼다. 바꿀 때 이전 값과 변경 이유를 같이 남긴다.
- 같은 피드백이 2번 이상 반복되면 `criteria.md` 규칙으로 올릴 것을 사용자에게 제안한다 (자동으로 올리지 않는다).
- `failures.md`는 "하지 말 것"을 확인할 때만 쓴다. 좋은 방법의 근거로 쓰지 않는다.

## 하루 작업 종료 시
- `log/YYYY-MM-DD.md` 작성 (템플릿: `log/_template.md`)
- 프로젝트 전체 진행은 `docs/progress.md`에도 한 줄 남긴다.
